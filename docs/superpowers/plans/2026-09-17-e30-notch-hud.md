# E30 — Cross-platform notch HUD Implementation Plan

**Status (2026-09-24): shipped differently.** The notch ships as a GNOME Shell extension (`crates/divisi-notch` + extension), not the iced window this plan describes; see the design doc and the chat tab added with the conversational spec.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship an opt-in, auto-hiding top-center notch HUD (`single-notch`) on macOS and Linux that polls `runtime.sock` for free-provider / agent-pool health and renders a collapsed pill → expanded card with fluid show/hide — without duplicating pool logic or embedding a GUI in `single-runtimed`.

**Architecture:** New workspace crate `single-notch` (binary `single-notch`) owns the iced UI, poller, view-model, animation state machine, and `cfg`-gated platform window setup. `single-core` gains `NotchConfig` + `SingleDirs` path helpers mirroring `mcp_gateway.toml`. `single-cli` gains a `Notch` subcommand that only manages config + companion process lifecycle (never embeds iced). v1 composes four existing NDJSON ops (`PoolStatus`, `ProviderKeyStatus`, `CoordinatorStatus`, `AgentList`); an optional composite `Request::NotchSnapshot` may land in the same release if four-poll chatter hurts. Approach A (pure-Rust iced) is locked; Approach B (SwiftUI macOS shell) is escape-hatch only if the Phase 1 spike fails macOS feel.

**Tech Stack:** Rust 2021 workspace; `iced` (+ `iced_layershell` or equivalent on Wayland); `winit`/`objc2` tweaks on macOS; existing `single-protocol` + Unix-socket NDJSON client pattern from `single-tui::client`; `toml` 0.8, `serde`, `anyhow`, `clap` 4. No WebView/Tauri. No push/event-stream IPC (still Phase 4 per ADR 0001).

**Spec:** `docs/superpowers/specs/2026-09-17-e30-notch-hud-design.md` (authoritative; this plan follows its §Build order 1:1 as Phases 1–8).

**Builds on:** E28 free-provider pool (`PoolStatusInfo`, `PoolKeyStatusInfo`, ledger/cooldowns) and E27 coordinator snapshots (`CoordinatorSnapshot`, `AgentInfo.authenticated`). Closest UX data reference: `single-tui` Pool pane poll of `PoolStatus` / `ProviderKeyStatus`.

### Task 6: `poll.rs` — fetch + `NotableEvent` diff

**Files:**
- Create: `crates/single-notch/src/client.rs`, `crates/single-notch/src/poll.rs`
- Modify: `lib.rs`
- Test: notable-event tests with fixture snapshots (no live socket in unit tests)

**Interfaces:**
- Consumes: `client::call(socket, &Request) -> Result<Response>` (clone of `single-tui::client::call`).
- Produces:
  ```rust
  #[derive(Debug, Clone, PartialEq)]
  pub enum NotableEvent {
      BenchAdded,
      BenchCleared,
      DegradedFlipped,
      GoalTerminal,          // success/fail entered terminal from prior non-terminal
      AuthLost,              // Authenticated → not
      HealthyRatioDrop,      // drop >= 0.25 absolute
  }

  pub fn diff_notable(prev: &NotchSnapshot, next: &NotchSnapshot) -> Vec<NotableEvent>;

  pub struct Poller {
      pub socket: PathBuf,
      pub poll_ms_idle: u64,
      pub poll_ms_active: u64,
  }

  impl Poller {
      /// Four-op compose. Later Phase 7 may try NotchSnapshot first.
      pub fn tick(&self) -> Result<(NotchSnapshot, Vec<NotableEvent>)>;
      pub fn interval_ms(&self, expanded: bool, notable_recent: bool) -> u64;
  }
  ```

  Diff rules (spec table, exact):
  - New bench / bench cleared → expand events
  - `degraded` flipped → event
